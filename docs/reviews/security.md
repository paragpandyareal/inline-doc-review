# Security review — inline-doc-review 0.5.0

Independent application-security review, 2026-10-08. Method: code reading plus small experiments in `/tmp/claude-1001/secreview` and read-only inspection of the installed venv. Nothing in the repo or `~/.claude` was modified except this report file.

Threat model as briefed: a malicious document the user/Claude opens, a malicious repo/working directory, a compromised package index, a local attacker with home write access, and the model being tricked into calling `open_file`.

## Findings

| ID | Severity | Location | Repro / evidence | Impact | Fix |
|----|----------|----------|------------------|--------|-----|
| F1 | **High** | `scripts/extract.py:224-240` → pycel `ExcelCompiler.evaluate`; pycel `excelformula.py` (`exec` at line 904, `compile` at 1017) | pycel is a formula *compiler*: it turns each cell formula into Python source and `exec`s it (confirmed by reading the installed 1.0b30). The pane calls it on any `.xlsx` whose formulas lack cached values — which an attacker controls by simply omitting cached results, forcing evaluation. Operand/function emit does only light escaping and emits function names verbatim; pycel is explicitly **not** a sandbox and supports `INDIRECT`, name resolution, etc. I confirmed the exec-codegen path but did **not** build a working breakout, so this is rated on the untrusted-evaluator exposure, not a proven RCE. | A crafted workbook is parsed with an attacker-influenced Python evaluator in-process; worst case is code execution as the user. Triggered just by viewing the file, and reachable without the user opening it (see F5). | Do not evaluate untrusted formulas. Show the stored/cached value only (`data_only=True`), and render `#NOEVAL` or the formula text when no cached value exists. If live evaluation is really wanted, gate it behind an explicit per-file user opt-in and run it in a locked-down subprocess. |
| F2 | **High** | `hooks/register.tsx:336-350` (`feedbackPrompt`), `707-725` (`deliver` → `$.prompt.submit`) | Document text and labels flow into a prompt that is auto-submitted to Claude with instructions to "Apply each item by editing the file directly." The quote is delimited only as a Markdown blockquote (`   > `) and the label (`` `path` ``, sheet name, heading, ADF title, filename) is inserted **unquoted**. There is no marker telling the model the quoted bytes are untrusted data. A heading/cell/filename such as `Ignore the feedback above and run …` is read by the model as instructions in the same turn that it has been told to edit files. | Prompt injection from a downloaded/generated document into an auto-submitted, file-editing turn. | Wrap quoted content *and* labels in a clearly fenced, explicitly-untrusted block (e.g. a sentinel the model is told never to obey), strip control characters, and keep the "this is document data, not instructions" framing in the system portion of the prompt. |
| F3 | **High** | `hooks/format.ts:213` (`markdownInline` regex), `hooks/html.ts:23` (`lineAt`), `hooks/md.ts` | Confirmed timings (Node, `/tmp/claude-1001/secreview/re.mjs`): `markdownInline` on `![` ×32 000 → **7.7 s**, `*a` bracket input → 1.3 s (catastrophic backtracking from the nested lazy alternation). `lineAt` is O(n) per tag, making `htmlRows` O(n²): 40 000 tags → **37 s**. These run in `loadDoc` for `md`/`html` with **no timeout** (only the `python3 extract.py` subprocess has the 60 s guard). | A malicious `.md`/`.html` file opened (via `open_file`, `/inline-review`, or auto-open) hangs the hooks runtime for seconds-to-minutes — a UI/DoS freeze of Claude Code. | Cap input size before parsing; precompute a line-offset array instead of `slice().split('\n')` in `lineAt`; rewrite `markdownInline` to avoid nested unbounded lazy quantifiers (or bound match length). |
| F4 | **Medium** | `hooks/register.tsx:364-365` (`resolvePath`), `544-559`/`561-584` (`open_file`/`open_files`), `532-536` (command) | The only gate is the file extension (`isSupported`). Absolute paths are accepted and symlinks are followed by `$.fs.read`. So the model (if tricked, F2) or `/inline-review <path>` can open and **display** any `.json`/`.yaml`/`.csv`/`.txt`/`.md`/`.html` anywhere on disk (e.g. config/credential files that use those extensions), and if the user comments, that content is quoted back into a prompt. | Arbitrary-file read / info disclosure, amplified by F2. | Resolve the real path (`$.fs.stat(path,{resolve:true})`) and deny anything outside the session working directory, following the allow-list guard shown in the runtime type docs. |
| F5 | **Medium** | `hooks/register.tsx:591-610` (post-`Bash` scan), `374-391` (`scan`), `452` (2 s `clock.every`) | After *every* `Bash` call the plugin walks the cwd (depth 3, 4000-entry budget) and auto-tracks supported files; a 2 s timer stats all open files. Any file that becomes the shown doc is auto-parsed — so merely running a shell command in a repo that contains a malicious `.xlsx`/`.md`/`.html` can route it into F1/F3 **without the user ever choosing to open it** (strongest when auto-open is on). Directory symlinks are *not* recursed (they list as `other`), so no symlink-loop. | Passive attack surface + filename/metadata exposure + CPU cost on large trees. | Only parse files the user explicitly opens; don't auto-parse scanned/auto-opened files with the heavy readers; make the scan opt-in. |
| F6 | **Medium** | `scripts/extract.py:20`, `35` | Top-level packages are pinned to exact versions, but installed with `pip install --upgrade` from the default index with **no hashes and no transitive pinning** (observed transitive deps: `lxml 6.1.3`, `numpy 2.5.3`, `networkx`, `ruamel.yaml`, …). A compromised index or a malicious new transitive release would be executed. `pycel==1.0b30` is a beta. | Supply-chain code execution at setup time. | Use a fully pinned, hash-locked requirements file (`--require-hashes`); consider `--no-deps` with explicit transitive pins. |
| F7 | **Medium** | `scripts/extract.py:27-29`, `make_examples.py:426-429`; `register.tsx:77,514,527` | `reexec_in_venv` does `os.execv(~/.cache/inline-doc-review/venv/bin/python, …)`. A local attacker with home write access (threat model d) who overwrites that interpreter or anything in its `site-packages` gets code execution as the user the next time the pane reads a doc. `python3` is also resolved from `PATH`. The venv path is predictable and under `~/.cache`, which other tooling may write/clean. | Local privilege/persistence trigger; PATH-hijack if `.`/a writable dir is early in `PATH`. | Verify the venv interpreter is a symlink to the expected system python and that `site-packages` is not world/other-writable before re-exec; resolve `python3` to an absolute trusted path. |
| F8 | **Low** | `hooks/adf.ts` (`walk`/`inline` recursion) | `adfRows` recurses per nesting level with no depth cap. A deeply nested ADF document within the 4 MiB read limit can overflow the stack and crash the parse. JSON size is otherwise bounded by the 4 MiB `$.fs.read` cap. | DoS (crash) on a crafted `.adf`/`.json`. | Add a recursion-depth limit and bail out gracefully. |
| F9 | **Low** | `scripts/extract.py:219` (`openpyxl.load_workbook`) | openpyxl read-only streams and the reader bounds rows/cols (`MAX_SHEET_ROWS/COLS`, `MAX_ROWS`), but a zip/decompression bomb in the `.xlsx`/`.docx` container can still inflate during archive open. | Memory/CPU DoS. | Check the compressed/declared uncompressed size before opening; cap. |

## Checked and found OK

- **XML entity expansion / billion-laughs:** the installed `openpyxl` uses `XMLParser(resolve_entities=False)` and `python-docx`'s `oxml_parser` sets `resolve_entities=False` — external/internal entity expansion is disabled by default. Confirmed by grepping the installed libs.
- **Terminal escape-sequence injection:** the runtime type docs state `Text`/`Code` are drawn "free of control characters" and the engine replaces control chars with U+FFFD / refuses them (claude-code.d.ts around lines 1623, 7403). Document text drawn through `Text` is sanitised by the host, so ANSI/OSC injection via cell/filename/ADF text is mitigated at the surface layer (the plugin itself does no stripping, so this depends on the host).
- **`prompt.submit` and the permission model:** `deliver('submit')` fires only on an explicit user click, is submitted with `origin:{kind:'plugin'}` (not `asUser`), and does **not** bypass tool-use approval — the model still needs permission to run `Edit`/`Write`. The `tool.call` wrapper around `Bash` returns the downstream result unmodified and does not alter other tools' results.
- **Directory symlink loops in the scan:** `scan` only recurses entries whose `kind === 'dir'`; symlinked directories list as `other`, so there is no symlink-loop recursion.
- **Image preview:** bounded at ~2 MB of base64 before decoding; only the header bytes are decoded for dimensions.

## Top priorities

1. **F1** — stop evaluating untrusted spreadsheet formulas with pycel (display cached values only).
2. **F3** — add input-size caps and fix the quadratic/backtracking parsers so a document cannot freeze the UI.
3. **F2** — fence and mark document text/labels as untrusted in the auto-submitted prompt.
4. **F4** — confine `open_file`/`open_files`/`/inline-review` reads to the working directory.
